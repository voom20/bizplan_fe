# BizPlan Frontend - 수동 테스트 시나리오

> **작성일**: 2025-12-20  
> **버전**: 1.0  
> **테스트 환경**: Chrome 브라우저, http://localhost:5173

---

## 📋 테스트 개요

이 문서는 BizPlan 프론트엔드 애플리케이션의 주요 기능을 수동으로 테스트하기 위한 시나리오입니다.  
각 시나리오는 **사전 조건**, **테스트 단계**, **예상 결과**로 구성됩니다.

---

## 🔐 TC-001: 회원가입

### 시나리오 1.1: 정상 회원가입

**사전 조건:**
- 브라우저에서 http://localhost:5173 접속
- 로그인되어 있지 않은 상태

**테스트 단계:**
1. 메인 페이지에서 우측 상단 "로그인" 버튼을 클릭한다.
2. 로그인 페이지에서 "계정이 없으신가요? 회원가입" 링크를 클릭한다.
3. 회원가입 페이지에서 다음 정보를 입력한다:
   - 이름: `홍길동`
   - 이메일: `test@example.com`
   - 비밀번호: `Test1234!`
   - 비밀번호 확인: `Test1234!`
4. "회원가입" 버튼을 클릭한다.

**예상 결과:**
- ✅ 비밀번호 강도 표시기가 "강함"으로 표시된다.
- ✅ 회원가입 성공 메시지가 표시된다.
- ✅ 로그인 페이지로 자동 이동된다.

---

### 시나리오 1.2: 비밀번호 불일치 오류

**사전 조건:**
- 회원가입 페이지에 접속한 상태

**테스트 단계:**
1. 이름: `테스트유저` 입력
2. 이메일: `user@test.com` 입력
3. 비밀번호: `Password123!` 입력
4. 비밀번호 확인: `DifferentPassword!` 입력 (의도적으로 다르게)
5. "회원가입" 버튼을 클릭한다.

**예상 결과:**
- ✅ "비밀번호가 일치하지 않습니다" 에러 메시지가 표시된다.
- ✅ 회원가입이 진행되지 않는다.
- ✅ 비밀번호 확인 필드에 빨간색 테두리가 표시된다.

---

### 시나리오 1.3: 이메일 형식 오류

**사전 조건:**
- 회원가입 페이지에 접속한 상태

**테스트 단계:**
1. 이름: `테스트` 입력
2. 이메일: `invalid-email` 입력 (@ 없이)
3. 비밀번호: `Test1234!` 입력
4. 비밀번호 확인: `Test1234!` 입력
5. "회원가입" 버튼을 클릭한다.

**예상 결과:**
- ✅ "올바른 이메일 형식이 아닙니다" 에러 메시지가 표시된다.
- ✅ 이메일 입력 필드에 빨간색 테두리가 표시된다.

## 🚀 TC-003: 프로젝트 생성

### 시나리오 3.1: 새 프로젝트 생성

**사전 조건:**
- 메인 페이지(http://localhost:5173)에 접속한 상태

3. 카드에 체크 아이콘(✓)이 나타나는지 확인한다.

**예상 결과:**
- ✅ 선택된 템플릿 카드가 하이라이트 된다.
- ✅ 버튼 클릭 시 Wizard Step 1 페이지로 이동한다.
- ✅ URL이 `/wizard/1`로 변경된다.

## 📝 TC-004: Wizard 단계별 진행

### 시나리오 4.1: Step 1 - 아이템 개요 작성

**사전 조건:**
- 프로젝트 생성 후 `/wizard/1` 페이지에 접속한 상태

**테스트 단계:**
1. 페이지 상단에 "Step 1" 표시가 있는지 확인한다.
2. 좌측 사이드바에서 현재 단계가 강조 표시되는지 확인한다.
3. 첫 번째 질문(사업 아이템)의 텍스트 영역에 다음을 입력한다:
   ```
   AI 기반 개인 맞춤형 건강 관리 앱입니다.
   사용자의 생체 데이터를 분석하여 최적의 운동과 식단을 추천합니다.
   ```
4. 입력 후 1-2초 대기한다.

**예상 결과:**
- ✅ 페이지 상단에 "Step 1: 아이템 개요"가 표시된다.
- ✅ 사이드바에서 Step 1이 현재 단계로 표시된다.
- ✅ 텍스트 입력 시 자동 저장 인디케이터가 표시된다.
- ✅ 저장 완료 후 "저장됨" 상태로 변경된다.

---

### 시나리오 4.2: Step 2로 이동

**사전 조건:**
- Step 1에서 내용을 입력한 상태

**테스트 단계:**
1. 페이지 하단의 "다음" 버튼을 클릭한다.
2. URL이 변경되는지 확인한다.
3. 페이지 상단의 단계 표시를 확인한다.

**예상 결과:**
- ✅ `/wizard/2` 페이지로 이동한다.
- ✅ "Step 2: 시장 분석"이 표시된다.
- ✅ 사이드바에서 Step 2가 현재 단계로 표시된다.

---

### 시나리오 4.3: 이전 단계로 돌아가기

**사전 조건:**
- Step 2 페이지에 접속한 상태

**테스트 단계:**
1. 페이지 하단의 "이전" 버튼을 클릭한다.

**예상 결과:**
- ✅ `/wizard/1` 페이지로 이동한다.
- ✅ 이전에 입력한 내용이 그대로 유지된다.

## 📊 TC-005: 재무 시뮬레이션 (Step 4)

### 시나리오 5.1: 재무 지표 입력 및 차트 확인

**사전 조건:**
- `/wizard/4` 페이지에 접속한 상태

**테스트 단계:**
1. 다음 값을 입력한다:
   - 목표 고객 수: `1000`
   - 고객 획득 비용(CAC): `50000`
   - 객단가: `30000`
   - 평균 구매 빈도: `3`
   - 고객 유지율: `80`
2. 입력값 변경 시 차트가 업데이트되는지 확인한다.
3. LTV, LTV/CAC 비율 등 계산된 지표를 확인한다.

**예상 결과:**
- ✅ 숫자 입력 시 실시간으로 차트가 업데이트된다.
- ✅ LTV = 30,000 × 3 × (1/(1-0.8)) = 450,000원이 표시된다.
- ✅ LTV/CAC 비율이 9.0으로 표시된다.
- ✅ 손익분기점 분석 차트가 표시된다.

---

### 시나리오 5.2: 손익분기점 분석

**사전 조건:**
- 재무 지표를 입력한 상태

**테스트 단계:**
1. 월별 매출 예측 차트를 확인한다.
2. 손익분기점(BEP) 표시를 확인한다.
3. 마우스를 차트 위에 올려 툴팁을 확인한다.

**예상 결과:**
- ✅ 12개월 매출 예측 라인 차트가 표시된다.
- ✅ 손익분기점이 빨간 점선으로 표시된다.
- ✅ 호버 시 해당 월의 매출/비용 정보가 툴팁으로 표시된다.

## 🎯 TC-006: PMF 진단 (Step 5)

### 시나리오 6.1: 설문 응답 및 점수 확인

**사전 조건:**
- `/wizard/5` 페이지에 접속한 상태

**테스트 단계:**
1. 각 PMF 질문에 대해 답변을 선택한다:
   - 질문 1: "매우 그렇다" 선택
   - 질문 2: "그렇다" 선택
   - 질문 3: "보통이다" 선택
   - ... (모든 질문 응답)
2. 응답할 때마다 점수 변화를 확인한다.
3. 모든 질문 응답 후 최종 PMF 점수를 확인한다.

**예상 결과:**
- ✅ 선택한 옵션이 하이라이트 된다.
- ✅ 응답 시 진행률 바가 업데이트된다.
- ✅ 최종 PMF 점수가 0-100 사이로 표시된다.
- ✅ 점수에 따른 등급(우수/양호/주의/위험)이 표시된다.

## 🔄 TC-010: 네비게이션 및 반응형

### 시나리오 10.1: 모바일 네비게이션

**사전 조건:**
- 브라우저 개발자 도구에서 모바일 뷰(375px)로 설정

**테스트 단계:**
1. 메인 페이지를 확인한다.
2. 햄버거 메뉴 아이콘을 클릭한다.
3. 메뉴에서 "로그인"을 선택한다.

**예상 결과:**
- ✅ 모바일에서는 햄버거 메뉴가 표시된다.
- ✅ 메뉴 클릭 시 사이드 패널이 열린다.
- ✅ 메뉴 항목 선택 시 해당 페이지로 이동하고 메뉴가 닫힌다.

---

### 시나리오 10.2: 브라우저 뒤로가기/앞으로가기

**사전 조건:**
- 메인 페이지에서 시작

**테스트 단계:**
1. 메인 페이지(/)에서 로그인 페이지(/login)로 이동한다.
2. 로그인 페이지에서 회원가입 페이지(/signup)로 이동한다.
3. 브라우저 뒤로가기 버튼을 클릭한다.
4. 브라우저 앞으로가기 버튼을 클릭한다.

**예상 결과:**
- ✅ 뒤로가기 시 /login 페이지로 이동한다.
- ✅ 앞으로가기 시 /signup 페이지로 이동한다.
- ✅ URL과 페이지 내용이 일치한다.

---

## ⚠️ TC-011: 에러 처리

### 시나리오 11.1: 404 페이지

**사전 조건:**
- 없음

**테스트 단계:**
1. 브라우저 주소창에 `http://localhost:5173/non-existent-page` 입력 후 이동한다.

**예상 결과:**
- ✅ 404 에러 페이지가 표시된다.
- ✅ "페이지를 찾을 수 없습니다" 메시지가 표시된다.
- ✅ "홈으로 돌아가기" 버튼이 제공된다.

---

### 시나리오 11.2: 네트워크 오류 처리

**사전 조건:**
- 백엔드 서버가 실행되지 않은 상태

**테스트 단계:**
1. 로그인 폼에 이메일과 비밀번호를 입력한다.
2. "로그인" 버튼을 클릭한다.

**예상 결과:**
- ✅ "서버에 연결할 수 없습니다" 에러 메시지가 표시된다.
- ✅ 에러 토스트가 화면에 표시된다.
- ✅ 애플리케이션이 크래시되지 않는다.
